# TreeAdmin: инструкция по эксплуатации

## 1. Назначение

TreeAdmin — консольное клиент-серверное приложение для удалённого выполнения команд на серверных узлах.

Приложение позволяет:

- запускать серверный узел;
- подключаться к серверу из клиентского режима;
- открывать удалённые shell-сессии;
- отправлять команды на выполнение;
- получать результаты команд сразу или позже;
- просматривать уведомления о завершённых командах;
- работать с несколькими серверами через клиентскую топологию;
- маршрутизировать запросы через промежуточные узлы;
- хранить результаты команд на сервере до получения клиентом.

Основной сценарий использования: один оператор управляет сервером или цепочкой серверов через консольный клиент.

---

## 2. Запуск приложения

Запуск выполняется из корня проекта:

```bash
python -m treeadmin
```

После запуска появится меню:

```text
Select mode:
1) Server
2) Client
0) Exit
```

---

## 3. Запуск серверной части

На машине, которая должна принимать команды, выбрать:

```text
1) Server
```

Ожидаемый вывод:

```text
Server started: http://0.0.0.0:8000
```

По умолчанию сервер запускается на:

```text
0.0.0.0:8000
```

Сервер принимает HTTP-запросы, создаёт shell-сессии, ставит команды в очередь, выполняет их через worker-потоки и сохраняет результаты до получения клиентом.

---

## 4. Запуск клиентской части

На машине оператора выбрать:

```text
2) Client
```

После запуска клиент проверяет известные серверы на наличие непрочитанных результатов и открывает меню:

```text
Client menu:
1) Connect to server
2) View notifications [N]
3) Ping server
4) Show topology
5) Reset config
0) Back
```

---

## 5. Настройка клиента

Конфигурация клиента хранится в файле:

```text
config/config_client.json
```

Минимальный пример:

```json
{
  "timeout": 10,
  "root_id": "pc1",
  "nodes": {
    "pc1": {
      "children": ["server1"]
    },
    "server1": {
      "host": "127.0.0.1",
      "port": 8000
    }
  }
}
```

Поля:

| Поле | Значение |
|---|---|
| `timeout` | таймаут HTTP-запросов |
| `root_id` | корневой узел клиента |
| `nodes` | список узлов топологии |
| `children` | дочерние узлы для построения маршрута |
| `host` | адрес сервера |
| `port` | порт сервера |

---

## 6. Проверка связи с сервером

В клиентском меню выбрать:

```text
3) Ping server
```

Если сервер доступен, клиент выведет ответ вида:

```text
CLIENT: GET: Hello, Client (status=200)
```

Ping используется для проверки доступности конечного сервера и корректности маршрута.

---

## 7. Подключение к серверу

В клиентском меню выбрать:

```text
1) Connect to server
```

Возможные варианты поведения:

### Если активных сессий нет

Клиент автоматически откроет новую shell-сессию:

```text
No active session on server1.
Opening new session...
```

### Если есть одна активная сессия

Клиент подключится к ней:

```text
Found active session 1 on server1.
Connecting...
```

### Если есть несколько активных сессий

Клиент предложит:

```text
1) Continue latest session
2) Choose session manually
3) Open new session
0) Back
```

---

## 8. Работа в удалённой shell-сессии

После подключения появится приглашение:

```text
[server1][session 1] /home/user >
```

Можно вводить обычные команды операционной системы:

Команды не выполняются прямо внутри HTTP-запроса. Они ставятся в серверную очередь, выполняются worker-потоком, а результат возвращается клиенту после завершения.

После отправки команды клиент показывает:

```text
Queued job 1 on session 1: ls -la
```

---

## 9. Служебные команды внутри shell

Внутри удалённой shell-сессии доступны специальные команды клиента:

| Команда | Назначение |
|---|---|
| `help` | показать справку |
| `jobs` | показать очередь, историю и pending-ответы текущей сессии |
| `sessions` | показать активные сессии на сервере |
| `pull` | вручную запросить готовые результаты |
| `patterns` | показать доступные шаблоны команд |
| `exit` / `quit` / `leave` | выйти из shell-окна, оставив удалённую сессию активной |
| `close` | закрыть удалённую сессию на сервере |

---

## 10. Разница между `exit` и `close`

### `exit`

```text
exit
```

Закрывает только локальное shell-окно клиента.

Удалённая сессия на сервере остаётся активной. Клиент переводит её в фоновый режим и продолжает периодически проверять результаты.

Использовать, если команда ещё выполняется или сессия может понадобиться позже.

### `close`

```text
close
```

Закрывает удалённую сессию на сервере.

После закрытия:

- сессия удаляется;
- queued-команды этой сессии отменяются;
- клиент забывает локальное состояние этой сессии.

Использовать, если работа с серверной сессией завершена.

---

## 11. Уведомления и результаты команд

Если команда завершилась, но оператор уже вышел из shell-сессии, результат можно получить через:

```text
2) View notifications
```

Клиент покажет серверы с непрочитанными ответами:

```text
Servers with unread responses:
  1) server1 — unread=2
  0) Back
```

После открытия результатов можно выбрать действие:

```text
1) Mark as read/delete from server
2) Ignore locally, keep on server
0) Keep unread
```

### Mark as read/delete from server

Результат удаляется из pending-ответов сервера.

### Ignore locally, keep on server

Результат скрывается только на текущем клиенте, но остаётся на сервере.

### Keep unread

Результат остаётся непрочитанным и будет показан снова.

## 12. Топология и маршрутизация

TreeAdmin может работать не только с прямым подключением:

```text
client -> server
```

но и с цепочками:

```text
client -> proxy -> server
```

Маршрут строится по `config/config_client.json`.

Пример:

```json
{
  "timeout": 10,
  "root_id": "pc1",
  "nodes": {
    "pc1": {
      "children": ["proxy1"]
    },
    "proxy1": {
      "host": "192.168.1.10",
      "port": 8000,
      "children": ["server1"]
    },
    "server1": {
      "host": "10.0.0.20",
      "port": 8000
    }
  }
}
```

Клиент строит путь от `root_id` до выбранного сервера. Промежуточный узел принимает запрос и пересылает его дальше, если сам не является конечным узлом маршрута.

## 13. Серверное хранилище

Сервер хранит очередь и результаты команд в локальном файловом хранилище.

Основные сущности:

| Раздел | Назначение |
|---|---|
| `queue` | команды, ожидающие выполнения или выполняющиеся |
| `history` | история завершённых команд |
| `responses` | готовые ответы, которые клиент ещё не подтвердил |

Рекомендуемая структура нового хранилища:

```text
data/
└── server_store/
    ├── state.json
    ├── state.json.bak
    ├── journal.jsonl
    ├── lock
    └── tmp/
```

Назначение:

| Файл / папка | Назначение |
|---|---|
| `state.json` | основное состояние очереди, истории и pending-ответов |
| `state.json.bak` | резервная копия последнего валидного состояния |
| `journal.jsonl` | журнал операций |
| `lock` | защита от второго экземпляра сервера на Linux |
| `tmp/` | временные файлы для атомарной записи |

---

## 14. Логи

Логи пишутся в директорию:

```text
logs/
```

Основные файлы:

```text
treeadmin-server.log
treeadmin-server-errors.log
treeadmin-server-audit.log
treeadmin-client.log
treeadmin-client-errors.log
treeadmin-client-audit.log
```

Переменные окружения:

```bash
TREEADMIN_LOG_LEVEL=INFO
TREEADMIN_LOG_DIR=logs
```

Пример:

```bash
export TREEADMIN_LOG_LEVEL=DEBUG
export TREEADMIN_LOG_DIR=/var/log/treeadmin
```

---

## 15. Полезные переменные окружения

### Логи

```bash
TREEADMIN_LOG_LEVEL=INFO
TREEADMIN_LOG_DIR=logs
```

### Серверное хранилище

```bash
TREEADMIN_MAX_OUTPUT_BYTES=524288
TREEADMIN_MAX_HISTORY_ITEMS=200
TREEADMIN_MAX_RESPONSES_ITEMS=100
TREEADMIN_MAX_QUEUE_ITEMS=100
```

### Опрос результатов клиентом

```bash
TREEADMIN_ACTIVE_POLL_INTERVAL=0.5
TREEADMIN_BACKGROUND_POLL_INTERVAL=7.0
```

## 16. Типовой рабочий сценарий

### На сервере

```bash
python -m treeadmin
```

Выбрать:

```text
1) Server
```

### На клиенте

```bash
python -m treeadmin
```

Выбрать:

```text
2) Client
```

Дальше:

```text
3) Ping server
1) Connect to server
```

В shell-сессии:

```bash
pwd
ls -la
cd /var/log
tail -n 50 syslog
exit
```

Позже проверить результаты:

```text
2) View notifications
```
